What is Gobii Remote MCP?

Gobii Remote MCP is a hosted Model Context Protocol endpoint that lets external AI clients operate persistent Gobii agents. Instead of exposing only a collection of app actions, it exposes agent lifecycle, messaging, timelines, files, coordination, and bounded event-waiting tools through a standard MCP interface.

MCP is the interface. Persistent agents are the product.

Durable by design

Your agent should outlive the chat that assigned the work

Most AI interactions begin and end inside one session. A Gobii keeps a charter, configuration, unified timeline, workspace, and working context of its own. Another client can add work to that same agent and inspect what happens next without creating a second task, run, or conversation model.

Connection

Connect once. Work with the same agents everywhere.

Client configuration syntax varies. The endpoint, transport, and credential rule remain the same.

  1. Create your account and API key

    Personal keys see agents available to that user. Organization keys operate within their organization scope.

  2. Add the Remote MCP endpoint

    Configure https://gobii.ai/api/v1/mcp/ as a Streamable HTTP server and send the key in an authenticated header.

  3. Discover tools and delegate

    Initialize the connection, call tools/list, then send work and read or wait on the agent's unified timeline.

Hermes configuration exampleStreamable HTTP
mcp_servers:
  gobii:
    url: "https://gobii.ai/api/v1/mcp/"
    headers:
      Authorization: "Bearer ${GOBII_API_KEY}"
    tools:
      include:
        - gobii_list_agents
        - gobii_send_agent_message
        - gobii_get_agent_timeline

Keep the key in the client environment or a managed secret store. Do not paste keys into shared configuration, chat, source control, or query strings. The Docs include initialization, tool calls, smoke tests, and the full catalog.

Security and control

Give clients access to the agents they are allowed to use

Remote MCP uses existing Gobii API keys. The endpoint does not claim OAuth support; every request carries the key whose scope governs the operation.

  • {% lucide "check" class="h-4 w-4" %}Personal and organization API keys retain their existing owner scope.
  • {% lucide "check" class="h-4 w-4" %}Every tool call executes with the permissions of the supplied key.
  • {% lucide "check" class="h-4 w-4" %}Browser-originated requests receive Origin validation to reduce DNS rebinding risk.
  • {% lucide "check" class="h-4 w-4" %}Debug output is bounded and conservatively redacts credentials and secret patterns.

Questions

Remote MCP FAQ

Concise answers for product evaluation. For live protocol details and client setup, use the Remote MCP Docs.

What is a remote MCP server?

A remote MCP server is a network endpoint that exposes tools or resources to compatible clients. Gobii's endpoint exposes authenticated tools for operating persistent agents rather than only app-specific actions.

How is Gobii Remote MCP different from the Gobii Agent API?

Use the Gobii Agent API when deterministic application code should call REST resources. Use Remote MCP when an AI client should discover available tools and select the appropriate operation. Both address the same persistent agent model.

Does a Gobii keep its context between MCP calls?

Yes. The MCP endpoint itself is stateless, but the Gobii is long-lived. Its charter, timeline, workspace, files, configuration, peer links, and working context persist between calls.

Which MCP clients can connect to Gobii?

Use an MCP-compatible client that supports remote servers over Streamable HTTP and can send a custom authentication header. Claude, Codex, and Hermes are compatibility examples, not endorsements or partnerships; configuration and security controls vary by client.

How is Remote MCP authenticated?

Send an existing Gobii API key on every request using X-Api-Key or Authorization: Bearer. Do not put the key in a query string.

Can I use Remote MCP with self-hosted Gobii?

Yes. The documented local endpoint is http://localhost:8000/api/v1/mcp/. Review the self-hosting guide and the open-source Gobii repository for deployment requirements.

Is Remote MCP the same as connecting an external MCP server to a Gobii?

No. Remote MCP lets an external client operate Gobii. A connected third-party MCP server moves in the opposite direction and gives a Gobii access to that server's tools or data.

Does the current endpoint support standalone SSE or MCP task augmentation?

No. V1 uses stateless Streamable HTTP requests, returns no MCP session ID, exposes no standalone GET SSE stream, and does not add MCP task or progress-stream abstractions. Use bounded event waiting and the durable timeline instead.
